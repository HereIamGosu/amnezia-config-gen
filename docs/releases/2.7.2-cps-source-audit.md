# Release 2.7.2 CPS / I1 Source Audit

Дата аудита: 2026-09-19. Область: Issue #5, генераторы CPS/I1 и их применение в `/api/warp`.

## Результат

До 2.7.2 режим QUIC создавал незашифрованный long-header packet с открытым CRYPTO frame, DNS создавал query, Auto включал неподтверждённые QUIC/DNS/DTLS, а неизвестное значение незаметно превращалось в Auto. Это не соответствовало заявленному поведению и затрудняло диагностику.

Политика 2.7.2:

| ID | Статус | Auto | Основание |
|---|---|---:|---|
| `static` | stable | да | существующий пул WARP-конфигураций проекта |
| `sip` | stable | да | существующая согласованная SIP-пара и WARP-конфигурации проекта |
| `stun` | stable | да | положительный отчёт Issue #5 и структурная проверка STUN/FINGERPRINT |
| `quic` | experimental | нет | RFC-корректные derivation, AEAD и header protection; live WARP interop не подтверждён |
| `dns` | experimental | нет | согласованная DNS response-shaped форма; live WARP interop не подтверждён |
| `dtls` | experimental | нет | структурная форма DTLS ClientHello; live WARP interop не подтверждён |
| `tls` | unsupported | нет | TLS не является поддерживаемой формой для UDP CPS; API возвращает 400 |

## QUIC-стратегия

Генератор создаёт один полностью защищённый QUIC v1 Initial-shaped packet на конфигурацию:

1. Случайные DCID/SCID, ClientHello random и X25519-shaped key share.
2. Initial secret и client keys выводятся по RFC 9001.
3. CRYPTO frame шифруется AES-128-GCM; header защищается AES-ECB mask.
4. Packet дополняется PADDING frames ровно до 1200 bytes.
5. CPS DSL делит готовый packet на два соседних fixed-byte `<b>`-тега (1000 + 200 bytes). Байты не выбрасываются и не заменяются runtime-операторами.

Это утверждение означает проверенную структуру и криптографическую внутреннюю согласованность, но не обещает успешный handshake в любой сети. До ручного interop QUIC остаётся experimental.

## DNS-стратегия

DNS CPS использует `<r 2>` для runtime Transaction ID и фиксированное согласованное response body: `QR=1`, `RCODE=0`, один question и один A answer с compression pointer на имя вопроса. Это ближе к upstream precedent, чем прежний query с EDNS0. WARP interoperability пока не подтверждён, поэтому DNS остаётся experimental.

## Ограничения доказательств

- Сервер не отправляет CPS-пакеты в сеть; он только создаёт конфигурацию.
- Автотесты доказывают структуру, derivation, AEAD round-trip, отсутствие усечения, API и конфигурационные инварианты.
- Live проверка требует реального клиента AmneziaWG 2.0/3.x и сети с наблюдаемым handshake/traffic; её результаты фиксируются в manual matrix.
- В проект не импортирован внешний исходный код и не добавлены зависимости.
