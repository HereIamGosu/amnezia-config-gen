# AmneziaWG Config Generator 3.1.2

## AWG 3.1 import on AmneziaWG iOS/macOS, and safe file names

Prepared on 2026-10-22 after 3.1.1 (`6cb62c9`).

## What changed for users

### AWG 3.1 config

The default AWG 3.1 `.conf` no longer contains the lines `RandomTrailers = off` and `DisableCookies = on`. AmneziaWG for iOS and macOS up to `v3.1.20260814` checks every `[Interface]` key against a fixed list and rejects the config on these two keys (`interfaceHasUnrecognizedKey`); versions from `v3.1.3` accept them. Every other line, its order and its values are unchanged.

- `RandomTrailers` stays off for Cloudflare WARP, as before; the line is simply not written (off is the engine default).
- `DisableCookies` is written only when you ask for it: `disableCookies=on` (or `off`) in the request. This supersedes the 2.7.1 default of `DisableCookies = on`. The setting only changes how a peer behaves as a responder under load, and a WARP client config only initiates handshakes, so the tunnel is probably unaffected (inference from the amneziawg-go source, not measured).
- With the two lines gone, the `.conf` of the AWG 3.0 and AWG 3.1 profiles is the same apart from random values. The 3.1 profile still offers the `vpn://` import with protocol version 3.1.

### File names

Downloaded configs are named like `AWGWarp31_k3f9.conf` (variants `AWGWarp31_k3f9_v2.conf`) instead of `AmneziaWarp-AWG3.1.conf`: letters, digits and underscore only, no dots, dashes or spaces, at most 32 characters, a different name for every generation so browsers do not add " (1)". Windows clients take the tunnel name from the file name. Whether the old name was the cause of any import error has not been checked on a Windows client.

### Client registry

The compatibility card no longer lists wg-tunnel for iOS (it is an Android app) and notes that AmneziaWG on Linux means the `awg` / `awg-quick` console tools.

## AWG profiles and the API

`/api/warp` accepts the same parameters. `disableCookies` is omitted from the output unless set; `awg.capabilities.disableCookies` reports `effectiveState: "disabled"` and `awg.enabledFeatures` has no `disable-cookies` by default. A client that parsed `DisableCookies` out of the default `.conf` must ask for `disableCookies=on`.

## Evidence boundary

- Checked in source: the key lists of AmneziaWG Apple `v3.1.20260814` (28 `[Interface]` keys, 5 `[Peer]` keys) and `v3.1.4` (30) against the generated config of every profile and option combination (`__tests__/client-key-conformance.test.js`, fixture from `scripts/extract-client-keys.js`).
- Not checked: a real AmneziaWG iOS/macOS or AmneziaVPN device. The parse rule is confirmed in the source; starting a tunnel on a device was not tried.
- Not checked: whether the old file names or the two removed lines caused import failures reported for AmneziaVPN 5.0.x on Windows.

## For developers

- `src/server/awg/configBuilder.js` does not write `RandomTrailers`; `warpSafety.js` and `api/warp.js` no longer default `disableCookies` to `on`; the capability `DisableCookies` is `opt-in` with the `amneziawg-apple` source (`v3.1.3`, `src/server/protocolEvidence.js`); `docs/protocol-evidence.md` is regenerated.
- `profiles.js`: the unused `explicitSafeFlags` is removed.
- `public/static/result.js`: `getModeFilename` builds the name.

## For the operator

A push to `main` deploys it. No host, controller or Endpoint Lab change. Smoke: `X-App-Revision`, `/`, `/en`, `/api/status`; a generation (it creates a WARP device) for AWG 3.1 without the two lines and one with `disableCookies=on`. Rollback: `amnezia-deploy rollback` returns 3.1.1.

npm ci
npm run lint
npm test
npm run evidence:check
npm run release:check
