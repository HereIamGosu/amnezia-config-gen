# Release 2.7.0 Source Audit

Scope: AWG 3.0 / 3.1 support for Cloudflare WARP-safe profiles.

This note records the upstream evidence used for the release implementation. It is intentionally narrow: official sources first, then only the minimum supporting references needed to close gaps.

## Official sources

### AmneziaWG protocol behavior

- `amnezia-vpn/amneziawg-go` README, tag `v3.1.20260828`
  - `https://raw.githubusercontent.com/amnezia-vpn/amneziawg-go/v3.1.20260828/README.md`
  - Confirms:
    - `range,x` accepts `a-b`, `a`, and `(off)`.
    - Omitted values are treated as `0`.
    - Header protection is AWG 3+ and requires `S1-S4 >= 12`.
    - Content padding is client-side and optional.
    - AWG 3+ timing fields exist as ranges: `RekeyAfterTime`, `RekeyTimeout`, `RejectAfterTime`, `KeepaliveTimeout`, `MaxHandshakeAttempts`, and `PersistentKeepalive`.
    - `PersistentKeepalive` range support is documented for AWG 3+.

- `amnezia-vpn/amneziawg-go` README, tag `v3.0.20260805`
  - `https://raw.githubusercontent.com/amnezia-vpn/amneziawg-go/v3.0.20260805/README.md`
  - Confirms the same range and AWG 3+ field semantics are already present in the 3.0 line.

- `amnezia-vpn/amneziawg-tools` releases
  - `https://github.com/amnezia-vpn/amneziawg-tools/releases`
  - Shows the release sequence:
    - `v3.0.20260805` with commit `9f70177`
    - `v3.1.20260812` with commit `ee0f0a9`
  - This is the clearest upstream version marker for the AWG 3.0 -> 3.1 transition.

### Cloudflare WARP firewall requirements

- Cloudflare One Client firewall docs
  - `https://developers.cloudflare.com/cloudflare-one/team-and-resources/devices/cloudflare-one-client/deployment/firewall/`
  - Confirms the current WARP ingress ports:
    - WireGuard default port `UDP 2408`
    - WireGuard fallback ports `UDP 500`, `UDP 1701`, `UDP 4500`
  - Also confirms the MASQUE path uses a different port set, which should not be conflated with the WireGuard/WARP-safe profile path.

## Version notes

- `amneziawg-go` 3.0 and 3.1 are both AWG 3+ lines; the README documents the same range and safety rules for both.
- `amneziawg-tools` release history shows `v3.0.20260805` and `v3.1.20260812` as the relevant upstream breakpoints for this release.
- `amnezia-client` current dev and `5.0.1.5` both expose `awgV3 = "3.1"`.
- `5.0.0.5` is the useful historical baseline for “before 3.1”.

## Evidence gaps

- I did not find an official upstream line that explicitly names the historical AWG 3.0 `vpn://` `protocol_version` value.
  - Current Amnezia client sources prove the key exists and that current dev uses `awgV3 = "3.1"`.
  - For the historical 3.0 value, treat any mapping as implementation-specific unless another upstream file or release note confirms it.
- Cloudflare docs show the current WARP ingress ports, but they do not provide a changelog proving those ports are unchanged over time.
  - For this release, treat the current docs as the authoritative firewall snapshot and keep the WireGuard/WARP-safe port set aligned with it.
- Upstream sources expose `RandomTrailers` / `DisableCookies` and `on` / `off` constants, but they do not define a WARP-specific safe default.
  - The release implementation should therefore be explicit about WARP-safe `off` choices and document them as local policy.

## Reusable takeaway

- Use `awgV3 = "3.1"` for current Amnezia client compatibility.
- Keep AWG 3.x timing fields and `PersistentKeepalive` as strict ranges, not loose integers.
- Emit `HeaderProtectionKey` only for native AWG peers, not for Cloudflare WARP.
- Treat `RandomTrailers` and `DisableCookies` as explicit opt-in AWG 3.1 fields; do not assume WARP compatibility from the upstream defaults.
- Preserve Cloudflare WARP WireGuard ingress ports at `2408`, `500`, `1701`, and `4500`.
