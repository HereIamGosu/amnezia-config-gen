# AmneziaWG Config Generator 3.1.1

## Route preset validation

Prepared on 2026-10-20 after 3.1.0 (`8381e78`).

## What changed for users

A request to `/api/warp` with route presets that do not exist (or a preset key with no usable characters) now gets HTTP 400 with the message "Неизвестные пресеты маршрутов: …" or "Не заданы домены для выбранных пресетов." The check runs before a WARP device is registered and before Lab Auto selects endpoints, so such a request no longer spends a registration. The web interface only sends presets from the catalog and is not affected. With `routeMode=full` the `presets` parameter is still ignored, as in 3.1.0.

## AWG profiles and the API

No change to config content, profiles, CPS, endpoints or the invariants I1–I11. The only API change is the response to the invalid input above.

## For developers

- `expandValidPresets` in `api/warp.js` holds the check (unknown keys; no domains and no static CIDRs) and is used by the handler and by `resolveAllowedIpsFromPresets`.
- Preset resolution starts while registration runs; it now has a no-op rejection handler so a registration failure cannot leave it unhandled. The rejection is still thrown at the later `await`.
- `__tests__/warp-presets-invalid.test.js`: 400 and zero Cloudflare calls for `bogus`, `telegram,zzz`, POST body, `!!!`; no Lab selection for an invalid preset; `routeMode=full` stays 200; a registration failure leaves no `unhandledRejection`.

## For the operator

A push to `main` deploys it. No host, controller or Endpoint Lab change. Smoke: `X-App-Revision`, `/`, `/en`, `/api/status`, one ordinary generation (it creates a WARP device). Rollback: `amnezia-deploy rollback` returns 3.1.0.
