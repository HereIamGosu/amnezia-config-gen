# AmneziaWG Config Generator 3.1.4

## `warpPort` no longer bypasses the port list

Prepared on 2026-10-25 after 3.1.3 (`410c885`).

## What changed for users

`/api/warp` has two parameters for the Endpoint port: `port` and `warpPort`. Only `port` was checked against the list of ports (2408, 500, 4500, 1701, 880, 8854); `warpPort` accepted any number from 1 to 65535, so `port=4500&warpPort=12345` produced a config with `Endpoint = engage.cloudflareclient.com:12345`. A value that was not a number or was `0` was ignored without an error.

Now an explicit `warpPort` outside the list is refused with HTTP 400. The body is the same as for an unlisted `port`: `error` (`Port … is not allowed. Use one of: …`) and `allowedPorts`. The check runs before a WARP device is registered and before Lab Auto selects endpoints. An empty `warpPort` counts as not given. Allowed ports and the default 4500 give the same configs as in 3.1.3. If both `port` and `warpPort` are allowed and differ, `warpPort` still wins, as before; if `port` is not allowed, the answer names `port`.

The web interface sends only values from its own port list, so it is not affected. A link or script that passed a port outside the list now gets the 400 and has to use one from the list.

## AWG profiles and the API

No change to profile fields, key order or the invariants I1–I11. Lab Auto changes only `Endpoint`, as before; a refused port is answered before it. The response format is unchanged except for the new refusal.

## Evidence boundary

- Reproduced on the 3.1.3 code with a test that calls the real handler without network: `port=4500&warpPort=12345` and `warpPort=65535` answered 200 with those ports in `Endpoint`.
- `__tests__/warp-port-allowlist.test.js` (new, 21 cases): each allowed port, the default, empty value, unlisted `warpPort` with and without `port`, differing ports, `0`, `65535`, `65536`, `-1`, `abc`, `1e3`, POST body, and refusal before Lab Auto and registration.
- Not checked: a live generation against Cloudflare (it registers a device); the reason Cloudflare accepts only these ports is taken from the existing allowlist comment in `api/warp.js`, not re-verified here.

## For developers

- `api/warp.js`: the port check in the handler loops over `port` and `warpPort` and uses `parseAllowlistedPort`.
- `parseWarpPort` still parses the value for the Endpoint; it is no longer the only gate.

## For the operator

A push to `main` deploys it. No host, controller or Endpoint Lab change. Smoke: `X-App-Revision`, `/`, `/en`, `/api/status`; `GET /api/warp?mode=awg2&warpPort=12345` must answer 400 with `allowedPorts` (it registers nothing). Rollback: `amnezia-deploy rollback` returns 3.1.3.
