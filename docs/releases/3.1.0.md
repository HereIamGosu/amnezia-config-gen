# AmneziaWG Config Generator 3.1.0

## CPS that changes every handshake, and the I1–I5 chain editor

Released on 2026-10-14 after 3.0.3 (`7db2546`, production at `27e3819`).

## What changed for users

### CPS now really changes between handshakes

The extra packets I2–I5 ("Enhanced", earlier "Enhanced mimicry") used to carry random bytes chosen once, when the file was created: every handshake of that config sent the same bytes. Now each of them is a chain of AmneziaWG tags — `<b 0x…>`, `<r N>`, `<t>` — and the variable parts are generated by the AmneziaWG client itself on every handshake. Only a few fixed bytes per field stay the same.

The generator uses only the tags that every client with I1–I5 understands. `<rd>` (random digits) and `<rc>` (random letters) exist since amneziawg-go 0.2.15, and an older client rejects a config that contains them as a whole, so they are not used automatically.

### CPS chain editor

Settings → Advanced → "Packets before the handshake (I1–I5)". In "Manual setup" each field is either automatic or your own chain:

- built from blocks — bytes, random bytes, random digits, random letters, time — or typed as text;
- with the packet size, the bytes that change on every handshake and the clients that accept it;
- "Compatibility": "All clients" (only `<b>`, `<r>`, `<t>`) or "Newer clients" (also `<rd>`/`<rc>`, amneziawg-go 0.2.15+);
- taken from a pasted `.conf` or from a config in the generation history; the settings link carries the chains.

The result summary lists the fields that use your own chains. They are checked for syntax and client compatibility only; they do not inherit the "stable/verified" status of the CPS protocol.

### Presets and error prevention

The section starts with four presets in one click: Standard (default, I1 only), Enhanced (plus I2–I5), More randomness (I2–I5 with digits and letters, for newer clients) and Manual setup. The separate "Enhanced mimicry" switch is now the Enhanced preset.

The manual editor does not let you build a config that a client would reject: hex accepts only hex digits, lengths stay within 1–1000, a packet cannot exceed 1472 bytes, a gap in I1–I5 is filled automatically, and replacing chains you made yourself always asks first.

### Fixed

- The settings dialog opened scrolled to where it was last left, below the tabs; it now always opens at the top.

## API

- New: `i1`…`i5` (query or POST body) and `cpsCompat` (`all` | `modern`, default `modern`) on `/api/warp`. Chains are checked by `public/static/cps-chain.js`, the same parser as the editor. Errors: HTTP 400 `cps_chain_invalid` (with `field`) and `cps_chain_gap`, both before any WARP registration.
- New: `appliedExtras.customCps` — fields that use own chains.
- Changed: `i1` in the request body was not validated before; unknown tags, `<d>`/`<ds>`/`<dz>`/`<c>`/`<wt>`, text outside tags and packets over 1472 bytes now return HTTP 400.
- Unchanged: without own chains the output of `/api/warp` has the same structure as in 3.0.3 (40 requests compared against the previous commit). Invariants I1–I11 hold; I9 now also covers own chains.

## Evidence boundary

Engine-level and live WARP verified; application-level manual matrix pending.

- Engine: every generated I2–I5 set and every config with own chains was applied with `Device.IpcSet` on nine amneziawg-go revisions, from `v0.2.13-beta-awg-1.5-fix6` to `master b5928ef` and `v3.1.20260814` (the revision in current AmneziaWG releases). See `docs/research/cps-runtime-tags-audit.md`.
- Live: userspace amneziawg-go master with real configs (with and without I2–I5, with own `<rd>`/`<rc>` chains) completed handshakes with Cloudflare WARP; on the wire the runtime bytes differed in every handshake.
- Not tested by hand: AmneziaVPN, AmneziaWG for Windows/Android/iOS, WG Tunnel; networks with DPI.

## For the operator

A push of the release to `main` deploys it (CI → GHCR → blue/green on the production VPS). No host, controller or Endpoint Lab change is needed. Smoke after the switch: `X-App-Revision` equals the release commit; `/`, `/en`, `/lab`, `/status.html` answer with `?v=3.1.0`; `/api/status` 200; one generation without own CPS and one with `cps5` and own `i1`…`i5`. Rollback: `amnezia-deploy rollback` returns 3.0.3.

npm ci
npm run lint
npm test
npm run build
npm run evidence:check
npm run release:check
npm run test:e2e
