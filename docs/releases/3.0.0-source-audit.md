## Protocol surface

- `buildFullConfig` and the interface builders, `src/server/awg/*`, CPS generators and payloads are unchanged. `api/warp.js` gains `endpointMode`: with `lab`, the `Endpoint` line takes `ip:port` from `LabEndpointProvider.selectForGeneration()` instead of `engage.cloudflareclient.com:<port>`; nothing else in the config depends on the source.
- Invariant tests I1–I10 pass unchanged. New I11 (`__tests__/invariant-i11-lab-auto.test.js`) generates every supported mode (Legacy, AWG 2.0, AWG 3.0, AWG 3.1) with 14 parameter variants in both modes through the real handler and requires the same sections, keys, order and values except `Endpoint` and the fields random by design (keys, junk sizes, CPS packets).
- Lab endpoints are limited to the Lab's WARP prefixes and the ports `2408`, `500`, `1701`, `4500` (`validateLabSnapshot`, the mirror of the Lab's `validate_snapshot`).
- `npm run evidence:check` passes; `docs/protocol-evidence.md` is unchanged.

## Consumers of changed data

- `/api/status`: Docker `HEALTHCHECK` and the deploy controller use the HTTP status only; the VPS monitoring stores `status`. The new `lab` field is ignored by them.
- `active-pool.json`: read by Lab Auto and by shadow mode, both through `LabEndpointProvider` on the read-only mount. Shadow mode observes hostname-mode requests only.

## Host and full-stack evidence

- Exporter host benchmark on a copy of the production Lab database: worst per-run export with production caps 0.41 s (limit 5 s), full uncapped cold export 2.0 s, peak RSS 33 MB.
- `0273cb4` installed on the host 2026-10-05 with backup and targeted smoke: refresh and discovery OK, ACTIVE 28, snapshot fresh, database, identity and key preserved, routes and `awg0` unchanged, no OOM or leaks; public files contain details only for ACTIVE/VERIFIED/SUSPECT, no negative control, blacklist, paths, exceptions, key or registration data.
- Runtime canary of the deadline fix (`46f6f02`): PASS for normal operating conditions; the degradation path was not naturally exercised and is covered by unit and mutation tests.
- Isolated full-stack run of this release candidate on the VPS (temporary container, production slot arguments, real read-only Lab mount, no nginx): hardening checks (read-only rootfs, no capabilities, non-root, limits, read-only mount, no Lab database, identity or key inside) passed; `/`, `/en`, `/lab`, `/en/lab`, `/api/lab`, `/api/status` answered; real WARP registrations in hostname mode and Lab Auto for all four modes, `count` 1–3 and ports 4500/2408/880 met I1–I10, Lab endpoints came from the live pool and differed from the hostname configs only in `Endpoint`; crafted Lab states (no files, malformed, stale, degraded, Lab unavailable, no ACTIVE) gave the expected page state and Lab Auto outcome. No Lab Auto request succeeded with another source. The container, image and files were removed and production was unchanged.

## Evidence boundary

The Lab proves endpoints from the project server with its own WARP identity. That an endpoint is reachable from a user's network is not proven, and the page says so. The full-stack run proved generation and endpoint selection, not a tunnel handshake of the generated configs from a user network.
