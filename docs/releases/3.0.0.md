# AmneziaWG Config Generator 3.0.0

## Endpoint Lab, Lab Auto and the new design

Prepared on 2026-10-06 as release candidate `rc/3.0.0`. Publication: annotated tag `v3.0.0` on the final release commit after the owner's decision; the GitHub Release page is created by the owner from this file.

3.0 ships three things together: a new interface, Endpoint Lab — a public, read-only view of WARP endpoints that the project checks itself — and a generator mode that takes the endpoint from that check. The default generation path is the same as in 2.7.4.

## What changed for users

### New interface

The site moves from the Win95 look to a dark design: a hero with a live "System status" card, a three-step flow (profile → parameters → generate) with chips that show the real settings, one "Generate" button, a result panel with variants and `.conf` / `vpn://` previews that hide the private key, shared dialogs that work on phones, an FAQ, and an English version at `/en`. The interface language follows the address (`/` Russian, `/en` English). Details are in the [changelog](../../CHANGELOG.md).

### Endpoint Lab

The project server checks Cloudflare WARP endpoints (`IP:UDP port`) with a real WireGuard handshake and HTTPS traffic through the tunnel, every minute for the current pool and in bounded discovery runs for new candidates. An endpoint that passes is ACTIVE for 7 minutes; it has to pass again to stay. The checks run from the project server, so they say that an endpoint works from there, not from every network.

- `/lab` and `/en/lab` show the pool: its health, how fresh it is, ACTIVE over time, recent events, the list of verified endpoints and the history of each one. The page is read-only and not indexed by search engines.
- `GET /api/lab` gives the same data as JSON (overview, or one endpoint with `?endpoint=<ip:port>&range=24h|7d|30d|all`). It only reads the files the Lab publishes and checks them before answering; without them it answers `503 lab_not_available`.
- The "System status" card on the main page has an "Endpoint Lab" row with a quick view.

### Lab Auto — endpoint from the Lab, or an honest error

In the generator settings, the "WARP endpoint" list has a new option, **Endpoint Lab — auto (verified IPs)** (`endpointMode=lab` in the API):

- every config gets its own endpoint from the fresh ACTIVE pool; with 2–3 configs the endpoints have different IPs;
- the chosen UDP port is a preference: if the Lab has too few fresh endpoints on it, other verified ports are used and the result says so;
- if the Lab has fewer distinct fresh endpoints than configs requested, you get fewer configs and a warning, never a repeated endpoint;
- if the Lab data is missing, stale or has no fresh endpoints, no config is created and the interface says why. Lab Auto never silently falls back to the hostname; choosing the hostname is your decision.

Lab Auto changes only the `Endpoint` line. Keys, addresses, DNS, AllowedIPs, MTU, AWG parameters (`S1..S4 = 0`, `H1..H4 = 1..4` for WARP), CPS packets, presets, the `.conf` format and `vpn://` import are produced exactly as in the hostname mode, for Legacy, AWG 2.0, AWG 3.0 and AWG 3.1 (invariant I11). Lab Auto is offered for the WARP profiles only; the self-hosted `awg2_random` template is refused.

### Hostname mode stays the default

`engage.cloudflareclient.com` with the chosen port is still the default and behaves as in 2.7.4. Its chip in step 2 now reads "Hostname" instead of "Автовыбор / Auto", because "auto" now means Lab Auto.

## Behaviour changes

- Chip label "Автовыбор / Auto" → "Hostname" (same behaviour).
- `/api/status` adds `lab: { available }`; existing fields are unchanged.
- `/api/warp` accepts `endpointMode` (`hostname` default, `lab`). An unknown value is `400 invalid_endpoint_mode`; `endpointMode=lab` with `peerEndpoint` is `400 endpoint_mode_conflict`; with a non-WARP template `400 lab_template_unsupported`. Lab Auto responses add `endpointSource: "lab"` per config and a `lab` object (`requested`, `selected`, `requestedPort`, `portMatched`, `ports`).
- Static assets move to `?v=3.0.0`.

## AWG profiles

No profile changes in 3.0: Legacy, AWG 2.0, AWG 3.0 and AWG 3.1 generate the same fields as in 2.7.4, and the protocol evidence of [2.7.3](2.7.3-source-audit.md) applies unchanged (`npm run evidence:check`).

## For the operator

Before deploying 3.0:

1. Endpoint Lab on the host runs a revision with the web export (`0273cb4` or newer); the release candidate was tested against `0273cb4`.
2. Update the installed deploy controller to this release's `deploy/controller/amnezia_deploy.py` (copy between `amnezia-deploy pause` and `resume`, `deploy/CONTROLLER.md`): it mounts the Lab public directory read-only independent of the shadow flag.
3. The push of the release to `main` deploys it (CI → GHCR → blue/green) and starts the IndexNow workflow for the changed public pages.

Rollback: `amnezia-deploy rollback` returns the previous release; the Lab keeps running independently. If only Lab Auto must stop, create `/etc/amnezia-deploy/endpoint-lab-public-off` and redeploy: Lab Auto then answers `503 lab_unavailable`, `/lab` shows "not available", hostname generation is unaffected.
