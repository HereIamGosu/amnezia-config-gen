# AmneziaWG Config Generator 3.2.1

## iPhone and iPad keep the result on screen; Metrica goal events are sent again

Prepared on 2026-11-07 after 3.2.0 (`0cd9312`). Config generation does not change: the server code (`api/`, `src/`,
`server.js`) is that of 3.2.0, so every `.conf`, `vpn://` link and response field is the same for the same request.

## What changed for users

**iPhone and iPad keep the result on screen.** On iOS (Safari, Chrome, Yandex and iPadOS in desktop mode) the page no
longer downloads the config right after generation. The result panel stays and says which button to press:
«Скачать .conf» or «Скопировать vpn://» (for AWG 3.0, which has no `vpn://` link, only the first). Other platforms
download automatically as before and the note names the downloaded file.

Why: in Yandex Metrica for 2026-10-10…11-06, 11 % of the iOS Safari users and 22 % of the iOS Chrome users who started
a generation got neither the success nor the error event, against 0 % in the Google app on iOS, where a download link
does nothing; the mean generation time was about 3 s on every OS. The download sheet of iOS takes the page away or
freezes it, and the panel with the `vpn://` link is lost. That this is the cause is a hypothesis; the release measures
it (see the evidence boundary).

**Events behind Metrica goals are sent again.** The Telegram channel buttons send `telegram_channel_cta_click`, the
event of the goal «Переход в Telegram-канал»; since the 3.0 redesign they sent another name and the goal stayed at
zero. `history_chains_used` is no longer dropped by the analytics allowlist, and copying the settings link sends
`settings_link_copied`. No keys, addresses, presets or config contents are sent.

**The counter runs only on awgconfig.com.** Local copies, test hosts and mirrors no longer load Metrica's `tag.js`
(17 hosts appeared in the entry-page report of the last 90 days). The `ym` queue still exists there, so the page does
not fail; the `<noscript>` pixel for visitors without JavaScript is unchanged.

## What did not change

Generation, the API, Endpoint Lab and invariants I1–I15. The "Recent changes" card lists 3.2.1, 3.2.0 and 3.1.9.

## Checks

`npm test`, `npm run lint`, `npm run test:e2e`, `npm run release:check`, `npm run evidence:check`,
`node scripts/check-asset-version-bump.js 0cd9312` (every changed `public/static` file comes with the new `?v=`).
The iOS path is covered by `__tests__/growth-telemetry-ios.test.js` and the iPhone cases of `e2e/generate.e2e.js`
(user agent of iOS Safari, 390×844): no automatic download, the note names the buttons, «Скачать .conf» still gives the
file.

## Evidence boundary

The iPhone cases run in desktop Chrome with an iOS user agent; no real iPhone or iPad was used. Whether the lost iOS
generations come back is not proven by this release: it is measured after deployment by comparing iOS with Android
for 28 days before and 14 and 28 days after it (the result-action share, start rate and repeated same-day
generations). No WARP registration was made for this release.
