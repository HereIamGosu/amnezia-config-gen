# AmneziaWG Config Generator 3.1.6

## The "Create config" button is removed

Prepared on 2026-10-26 after 3.1.5 (`c569ac2`).

## What changed for users

3.1.5 put a "Create config" button above the feature chips in the header block. In the browser it sat flush against the chips below, with a gap above and none underneath, and the owner reported it as crooked. The button is removed together with its style and the `hero_cta` string.

The button was also of little use. On a desktop screen the generator starts right under the header block. On a 375 px screen the anchor scrolled the page to the generator, but the "Generate configuration" button was still about 400 px below the visible area (the second round of simulated first-time visitors measured `y=970` against a 667 px screen). The other 3.1.5 changes stay: the note that the file is already downloaded, the "Next" line, the plain error texts, the Endpoint Lab hint, one file on a double click on "Download .conf".

## "Endpoint Lab" is no longer cut off

The 3.1.5 hint under "Unavailable" in the status block read "the config will use hostname". It does not wrap, so it took the width of the row and the name showed as "Endp…" on a 1280 px screen. It now reads "via hostname" (ru: "через hostname"). Checked in a browser at 1280 px (ru and en) and at 375 px with the panel opened: the name is whole.

## AWG profiles and the API

No change to the `.conf` text, profiles, CPS, `vpn://`, ports, Lab or the API. No server code changed. Invariants I1–I11 are not touched.

## Evidence boundary

- The layout defect is read from a screenshot sent by the owner and from the 3.1.5 CSS (the button had a top margin and no bottom margin next to the chips); it was not measured in a browser. After the removal the header block has the markup and styles it had in 3.1.4.
- The claim that the button did little rests on the QA runs of 2026-10-26: language-model agents driving a browser against a local server, one run per role per round. They are not real visitors.
- `__tests__/first-path-ux.test.js` now checks that `#heroCta` and the `hero_cta` strings are absent.
- The "scroll to the generate button on a phone" snag is not solved by this patch: the generate button stays below the first screen on a 375 px device.

## For developers

- `public/locales/{ru,en}.json` and the fallback in `public/static/status.js`: `status_lab_fallback_hint` shortened.
- Removed: the `<a id="heroCta">` block in `public/index.html` (and the generated `public/en/index.html`), `.hero__cta` in `public/static/styles.css`, `hero_cta` in `public/locales/{ru,en}.json`.
- `__tests__/first-path-ux.test.js`: the "hero links to the generator" test became "hero has no extra call-to-action".

## For the operator

A push to `main` deploys it. No host, controller or Endpoint Lab change. Smoke: `X-App-Revision`, `/` and `/en` have no `id="heroCta"` and use `?v=3.1.6`. Rollback: `amnezia-deploy rollback` returns 3.1.5.
