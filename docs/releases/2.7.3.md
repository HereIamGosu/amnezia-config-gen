# AmneziaWG Config Generator 2.7.3

## Protocol Evidence & Release Consistency

Prepared on 2026-10-03. Publication date is pending the final commit, tag, and GitHub Release.

2.7.3 is a patch release for protocol evidence and release consistency. It does not add a new AWG button, endpoint selection rule, bypass promise, or recovery assistant. The user-visible WARP-safe output remains aligned with the 2.7.1/2.7.2 policy while the project makes that policy inspectable and release-gated.

## What changed

- Package metadata moved to `2.7.3`.
- Frontend static asset cache keys moved to `?v=2.7.3`.
- `npm run release:check` now verifies package/lockfile coherence, changelog entry, release note and source audit presence, asset cache keys, and release ledger/process files.
- CI now runs `npm run evidence:check` and `npm run release:check`; tag builds also validate that `vX.Y.Z` matches `package.json`.
- The release ledger records the current 2.7.x tag/release gap without inventing historical tags.

## Protocol policy summary

The intended 2.7.3 policy is documentation/evidence consistency, not feature promotion.

| Area | Effective 2.7.3 policy |
| --- | --- |
| AWG 3.0 | WARP-safe client-side profile remains enabled. |
| AWG 3.1 | WARP-safe client-side profile remains enabled. |
| ContentPaddingAddition | Supported for AWG 3.0 and 3.1, default `10-100`, disableable by `off`, `0`, or `0-0`. |
| DisableCookies | AWG 3.1 default `on`, local client behaviour, disableable by `disableCookies=off`. |
| RandomTrailers | Remains blocked for WARP. |
| HeaderProtectionKey | Remains unavailable for WARP. |
| S1-S4 | Fixed to `0` for WARP. |
| H1-H4 | Fixed to `1`, `2`, `3`, `4` for WARP. |
| CPS Auto | Stable/verified pool only: Static, SIP, STUN. |
| CPS explicit experiments | QUIC, DNS, and DTLS remain explicit experimental choices. |
| CPS TLS/unknown | Unsupported/unknown values return controlled errors. |

## Release consistency

The release checker is intentionally offline and deterministic. It does not call GitHub, create tags, or validate remote releases during normal test runs.

Remote state verified during preparation:

- remote tag present: `v2.7.0`;
- remote tags missing: `v2.7.1`, `v2.7.2`, `v2.7.3`;
- GitHub Releases visible through the public API: `v2.7.0`, `v2.2.0`;
- `v2.7.1` and `v2.7.2` release notes exist in the repository but have no matching remote tags/releases.

This release records that inconsistency in the ledger instead of guessing historical tag targets.

## Operator notes

Before publishing `v2.7.3`, run:

```bash
npm ci
npm run lint
npm test
npm run build
npm run evidence:check
npm run release:check
git diff --check
```

Then create an annotated tag only after the final commit is selected:

```bash
git tag -a v2.7.3 -m "Release 2.7.3 - Protocol Evidence & Release Consistency"
```

Do not create or move historical `v2.7.1` / `v2.7.2` tags unless the exact release commits are proven and the repository owner explicitly approves the remote mutation.
