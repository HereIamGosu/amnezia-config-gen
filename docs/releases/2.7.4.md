# AmneziaWG Config Generator 2.7.4

## Honest Status & Cache Refresh

Prepared on 2026-10-03. Publication: annotated tag `v2.7.4` on the final release commit; the GitHub Release page is created by the owner from this file.

2.7.4 is a bugfix release. It does not change AWG profiles, CPS selection, endpoint selection, or any protocol knob. It corrects what the service reports about itself and makes sure browsers actually load the corrected frontend.

## What changed

### Endpoint status semantics

`/api/status` used to derive port health from the number of candidates in the built-in endpoint list: a port without candidates became `down` and the pool `degraded`. Nothing was measured, so the status was permanently yellow and the main page showed an English "Some ports have reduced availability" banner.

The states are now defined in `src/server/endpointStatus.js`:

| State | Meaning |
| --- | --- |
| `ok` | Runtime health data exists and every measured endpoint passes (success rate ≥ 0.5). |
| `degraded` | Runtime health data shows some measured endpoints failing. |
| `down` | Runtime health data shows every measured endpoint failing. |
| `unknown` | No runtime health data. Not evidence of a failure. |

An endpoint is measured only when the registry recorded a check (`last_checked_at` and a finite `tcp_success_rate_24h`). The overall state ignores unknown ports while any port has data. The built-in list has no measurements, so today the pool reports `unknown`.

Response, additive: `candidates` (addresses per port) and `health_source` (`none` | `runtime`). `status`, `ports`, `active_endpoints`, `message`, `cache_source`, `updated_at` are kept. A failure to compute the status also yields `unknown`.

UI: the status card shows "НЕТ ДАННЫХ / NO DATA" with "built-in list · availability is not measured"; the main page banner appears only for measured `degraded`/`down` and is localized.

### Live service status

The status modal and `status.html` read live `/api/status` + `/api/healthcheck` (8 s timeout, honest "temporarily unavailable" state with the next attempt time, polling only in a visible tab, Retry-After honoured, stale renders cleared even after device sleep). The committed `public/status.json` and the GitHub snapshot workflow are gone. `/api/healthcheck` also probes TCP reachability of `iplist.opencck.org`.

### Endpoint source label

After the Vercel KV removal the result summary still called a TCP-checked candidate from the built-in list "KV". It is now labelled "встроенный список, проверка TCP / built-in list, TCP-checked". Metrika telemetry reports `endpoint_source=tcp_check` instead of `kv` for the same case.

### Cache refresh and guard

Static assets under `public/static/` are cached for a year as `?v=<version>`. Commits after the 2.7.3 release (`a2625d0`..`c0e91ec`) changed `script.js` and added `live-status.js` under the unchanged `?v=2.7.3` key, so some browsers kept the old files. Cache keys move to `?v=2.7.4`, and CI now fails when an immutable asset changes without a version bump (`scripts/check-asset-version-bump.js`). `npm run release:check` now verifies the cache keys of `status.html` as well as `index.html`.

`presets-fallback.json` (loaded without `?v=`) was meant to be revalidated, but the general `/static/(.*)` immutable rule overrode its exception because the last matching header rule wins. The exception now comes last, so updated offline preset catalogues reach browsers.

### Maintenance included since 2.7.3

- Unused Vercel KV integration removed; endpoint registry contract unchanged.
- Docker base image pinned by digest; Dependabot for the base image and GitHub Actions.
- CI: workflow permissions default to none, actions pinned to commit SHAs (checkout, setup-node, upload-artifact now v7), the Docker image is built once and that exact image is smoke-tested. No automatic deployment.

## Protocol policy summary

Unchanged from 2.7.3: WARP keeps `S1..S4=0`, `H1..H4=1..4`, MTU and AWG 3.x client-side profiles as documented in [protocol evidence](../protocol-evidence.md); CPS Auto uses the verified Static/SIP/STUN pool; QUIC/DNS/DTLS remain explicit experiments; TLS/unknown CPS values return controlled errors.
