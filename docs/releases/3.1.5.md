# AmneziaWG Config Generator 3.1.5

## Hints on the way to the first config

Prepared on 2026-10-26 after 3.1.4 (`f5bf2ba`).

## What changed for users

The page downloads the `.conf` right after "Generate configuration", without a click on "Download". Four simulated first-time visitors (an impatient one, a sceptic, a phone user on a throttled 3G link, a stress tester) all reached the config in one to two clicks, and all four stopped at the same place: the file had gone to the downloads folder and nothing said so. This release fixes that and the smaller snags they met on the same path.

- **The result says the file is downloaded.** Under the buttons: "File AWGWarp2_xxxx.conf is already downloaded. Can't find it in your downloads? Press "Download .conf"". Below it a "Next" line (import the `.conf` into AmneziaVPN or AmneziaWG, or paste the `vpn://` link into AmneziaVPN) with a link to the detailed instructions.
- **"Create config" button in the header block** scrolls to the generator. On a 375 px screen the generate button used to sit about 1600 px below the top.
- **Endpoint Lab "Unavailable"** now says "the config will use hostname" next to it; the status block no longer reads as a contradiction beside "Everything works".
- **Refusals before the request** (split tunnelling with no direction selected, an error in a custom CPS chain) also appear as a toast, not only as the small grey line under the button.
- **A double click on "Download .conf"** gives one file, not two.
- **Error texts.** A network failure reads "No connection to the server. Check your internet and try again."; HTTP 429 "Too many requests. Wait a minute and try again."; 5xx "The server is temporarily unavailable (code N). Try again in a minute."; an HTML page instead of JSON "The server returned a page instead of data. Reload the page and try again." (it told visitors to run `vercel dev`). Errors that carry their own message from the API are shown as before.

## AWG profiles and the API

No change to the `.conf` text, profile fields, key order, CPS, `vpn://`, ports or Lab. Invariants I1–I11 are not touched. No server code changed.

## Evidence boundary

- The visitors were language-model agents driving a browser against a local `server.js` with the Cloudflare registration stubbed (no device was registered); they are not real people, one run per persona per round. Click counts are not comparable between rounds because each persona chooses what to read and what to break.
- Round 1 ran on 3.1.2 code, round 2 on 3.1.4 plus these changes. In round 2 the same four roles reached the config again and the new note, button and error texts were seen; the hints are not proven to change what real visitors do.
- `__tests__/first-path-ux.test.js` (new) checks the sources and both locale files: the new keys and placeholders, the 429/5xx mapping, that a network failure stays a `TypeError` (the generation telemetry classifies it as `network` by that), that the note is hidden unless the result carries a file name, the hero link.
- Checked by hand in a browser: the offline and 429 texts, the toast for an empty split tunnel.
- Not done: the 44 px touch targets (the project uses 40 px on purpose), the Metrika iframe blocked by `frame-src 'none'` (console noise, loosening the CSP was not part of this patch), the slow first open of the Endpoint Lab window, silent correction of the I1–I5 fields, the unexplained disabled IPv6 switch in mobile mode, settings not surviving a reload. Findings about the privacy text, terms and donation link were only recorded.

## For developers

- `public/static/script.js`: `httpErrorMessage(status)`, `showGuardMessage(status, text)`, the `.catch` on the `/api/warp` fetch rethrows a `TypeError`; `showResult` receives `autoDownloaded` (the file name).
- `public/static/result.js`: `#resultAutoNote`, a 1.2 s guard on the Download click.
- `public/static/status.js`: the detail text of the "unavailable" Lab state.
- `public/index.html`, `public/en/index.html` (generated), `public/static/styles.css`, `public/locales/{ru,en}.json`: new keys `err_network`, `err_rate_limited`, `err_server`, `hero_cta`, `status_lab_fallback_hint`, `result_autodownload_note`, `result_next_steps`, `result_next_instruction`, `changes_315_*`; `err_html_response` reworded.

## For the operator

A push to `main` deploys it. No host, controller or Endpoint Lab change. Smoke: `X-App-Revision`, `/`, `/en` (the "Create config" button and `?v=3.1.5` on the assets), generate once with the default settings and check the note under the buttons. Rollback: `amnezia-deploy rollback` returns 3.1.4.

```bash
npm ci
npm run lint
npm test
npm run evidence:check
npm run release:check
```
