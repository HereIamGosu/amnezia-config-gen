# AmneziaWG Config Generator 3.2.2

## «Подключилось?» after the result, «Поделиться» after «Да»

Prepared on 2026-11-07 after 3.2.1 (`b33a3b8`), the same day. Config generation does not change: the server code
(`api/`, `src/`, `server.js`) is that of 3.2.0, so every `.conf`, `vpn://` link and response field is the same for the
same request.

## What changed for users

**«Подключилось?» after the result.** In visits with a successful generation there were 1.9 successful generations
on average (Yandex Metrica, 2026-10-10…11-06), and whether the tunnel then connected was not measured at all. The
result panel now asks it, in place of the «Дальше» hint, so the panel does not change height. The question appears once
the visitor has done something with the config: downloaded it, copied the `vpn://` link or the text, opened it in full;
after an automatic download (every platform but iOS) it appears when the visitor comes back to the tab. One answer per
generation; the question can be closed without answering; there is no text field.

**«Нет»** lists what to try, in the order of the FAQ answer on configs that import but do not connect:

1. the other endpoint: Lab Auto ↔ hostname (not offered for hostname while Endpoint Lab has no fresh data);
2. a profile more clients accept (AWG 3.x → 2.0, 2.0 → 1.5, after `src/server/clientCompatibility.js`);
3. that FAQ answer (port, mobile profile, DNS and routes);
4. the Telegram channel.

The buttons only change the setting and point to «Сгенерировать конфигурацию»: every generation registers a new WARP
device, so the visitor starts it.

**«Да»** offers to share the site: Telegram, copy link and, on phones, the system share sheet. The link is the home
page of the page language with `utm_source=share&utm_medium=telegram|copy|native`; the config and the `vpn://` link
(they hold the private key) are never shared. `robots.txt` cleans the `utm_*` labels for Yandex, and the canonical URLs
carry no parameters.

**Metrica events.** `connection_works` and `connection_fails` with the profile, endpoint, CPS, mobile and router fields
of the generation; `connection_next_step` with the step; `share_clicked` with the channel. No keys, addresses, presets,
text or config contents.

## What did not change

Generation, the API, Endpoint Lab and invariants I1–I15. If `result-feedback.js` fails to load, the result panel works
as in 3.2.1, without the question.

## Checks

`npm test`, `npm run lint`, `npm run test:e2e`, `npm run seo:check`, `npm run release:check`, `npm run evidence:check`,
`node scripts/check-asset-version-bump.js b33a3b8`. The behaviour is covered by
`__tests__/growth-connection-share.test.js` and six cases of `e2e/generate.e2e.js`: when the question appears (and
without a layout shift), «Да» and the share links, «Нет» and its steps without a request to `/api/warp`, closing, one
answer per generation, RU → EN, iPhone, and the page without `result-feedback.js`.

## Evidence boundary

Released the same day as 3.2.1 by the owner's decision, so the effect of 3.2.1 on iOS cannot be separated from this
release in before/after comparisons. The iPhone case runs in desktop Chrome with an iOS user agent. How many visitors
answer, and whether the steps reduce repeated generations, is measured only after deployment. No WARP registration was
made for this release.
