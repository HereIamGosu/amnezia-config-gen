## Protocol surface

No file that defines generated configuration changed between 2.7.3 and 2.7.4:

- `src/server/awg/*`, CPS generators and payloads, `api/warp.js` profile/endpoint logic: unchanged except the removed fire-and-forget KV health write (a no-op without KV credentials, which were never configured) and comments; endpoint candidates and the TCP pre-check are the same.
- `npm run evidence:check` passes; `docs/protocol-evidence.md` is unchanged.
- WARP invariants (`S1..S4=0`, `H1..H4=1..4`, MTU, uppercase `I1`, AWG 2.0 field order, RandomTrailers/HeaderProtectionKey blocked) are covered by the existing invariant tests, which pass unchanged.

Upstream revisions pinned in the 2.7.3 audit were not re-evaluated because no protocol decision depends on this release.

## Consumers of `/api/status`

Checked before changing the status semantics:

- Docker `HEALTHCHECK` and `deploy/deploy.sh` use the HTTP status code only.
- The VPS monitoring collector stores the `status` field as `app_status`; the Telegram ops bot only displays it. No alert rule depends on it.
- Frontend: main page banner and status modal, both updated in this release.
