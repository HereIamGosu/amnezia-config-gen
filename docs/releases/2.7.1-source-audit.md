## Классификация параметров

Категории: **A** — требуется совместимый/matching remote peer; **B** — локальное поведение; **C** — меняет исходящий transport, но остаётся допустимым stock WireGuard input; **D** — доказательств недостаточно.

| Параметр | Категория | Доказательство | WARP policy 2.7.1 |
|---|---:|---|---|
| `Jc/Jmin/Jmax` | B | Sender создаёт отдельные junk datagrams до handshake; Cloudflare не требуется знать значения | поддерживается |
| `I1-I5` | B | CPS datagrams генерируются sender-side и не меняют WireGuard handshake | поддерживается |
| `S1-S4` | A | Receive classification вычисляет prefix padding по локальным `paddings.*` | жёстко `0` |
| `H1-H4` | A | Receive classification проверяет локальные header ranges | жёстко `1,2,3,4` |
| `HeaderProtectionKey` | A | Header cipher применяется на send и receive; nonce использует S-prefix | запрещён |
| `ContentPaddingAddition` | C | `send.go` добавляет zero padding до AEAD `Seal`; `receive.go` после AEAD `Open` обрезает IPv4/IPv6 пакет по header length | default `10-100`, строгий override/off |
| `RekeyAfterTime` | B | Локальные timers | поддерживается |

| `DisableCookies` | B | `receive.go` проверяет `!disableCookies && IsUnderLoad()` только перед локальной генерацией Cookie Reply/MAC2 rate limiting | AWG31 default `on`, строгий toggle |

Категория D после проверки не осталась. Это не означает, что реальная WARP interoperability была проверена локально: таблица описывает доказанную семантику исходного кода.

## ContentPaddingAddition

Доказано по `device/send.go`: дополнительный padding добавляется к plaintext transport payload до `keypair.send.Seal`, поэтому он аутентифицирован AEAD. По `device/receive.go` расшифрованный payload обрезается до IPv4 `Total Length` или IPv6 `Payload Length`, как в обычном WireGuard receive path. Remote peer не читает диапазон и не участвует в handshake.

Размер ограничивается изученным `udpWindow`; при недостатке места addition уменьшается. При WARP `MTU=1280` это снижает риск фрагментации, но не является доказательством поведения всех сетей. Нужен ручной throughput/UDP/rekey тест.

Parser/ABI nuance: Go UAPI хранит `UintRange` с `uint32` bounds, а текущий официальный `.conf` parser `amneziawg-tools/src/config.c` хранит `ContentPaddingAddition`, timings и `PersistentKeepalive` через `u16_range_t`. Генератор валидирует публичный `.conf` контракт как `0..65535`; `65536` не допускается. `0`, `0-0` и `off` нормализуются как disabled для полей с disable semantics.

## DisableCookies

Флаг не меняет Handshake Initiation/Response wire format и не отключает `cookieGenerator.ConsumeReply`: входящий Cookie Reply продолжает обрабатываться. Он подавляет только локальную ветку, которая под нагрузкой проверяет MAC2/rate limiter и отправляет Cookie Reply.

Это anti-fingerprinting trade-off, не security improvement: локальная Cookie Reply anti-DoS защита отключается.

## RandomTrailers

`SendHandshakeInitiation`, `SendHandshakeResponse` и `SendHandshakeCookie` могут добавить байты после фиксированного handshake message. `DeterminePacketTypeAndPadding` принимает удлинённый handshake только если receiver-side `randomTrailers` включён, после чего receive path обрезает packet до фиксированного размера. Stock WireGuard эквивалентной ветки не имеет и ожидает точный размер handshake.

Для peer-specific send path размер trailer зависит от изученного `peer.udpWindow`. До появления достаточного окна `randomTrailer` может вернуть ноль; поэтому наблюдение «сначала работает» не доказывает стабильность через rekey. Эта последовательность подтверждена как возможная по коду, но не воспроизведена с Cloudflare в этой задаче.

## AWG 3.0 / 3.1 и vpn://

Текущий `amnezia-client` определяет любой набор AWG3 markers как `awgV3`, а `awgV3` равен строке `3.1`. Отдельной подтверждённой `protocol_version` для исторического AWG 3.0 не найдено. Поэтому `awg3` остаётся `.conf`-only, а `awg31` использует `protocol_version=3.1`.

## Решение для WARP

| Механизм | Решение |
|---|---|
| Content padding | включён по умолчанию `10-100`; можно отключить/переопределить |
| Disable cookies | AWG31 default `on`; можно поставить `off` |
| Random trailers | всегда `off`; попытка `on` даёт HTTP 400 |
| Header protection | запрещён; попытка override даёт HTTP 400 |
| S/H | финальный safety layer принудительно восстанавливает `0/1..4` |

## Что не проверено

- Реальный Cloudflare WARP handshake, browsing, DNS, large TCP, UDP, idle/rekey/reconnect.
- Поведение конкретных mobile/router клиентов и прошивок.
- Производительность `ContentPaddingAddition=10-100` на сетях с меньшим фактическим path MTU.

Эти пункты нельзя заменить unit/integration тестами генератора.
