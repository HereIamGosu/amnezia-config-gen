# Release 3.2.0 — Source Audit

Checked on 2026-11-01 from `6f122d1` (3.1.9 plus its ledger commit). No upstream WireGuard/AmneziaWG source was read: the release changes where the routes of a split config come from, which preset keys exist, and which routes and endpoints one config may hold together; the wire format, AWG profiles, CPS, the `vpn://` schema and the Endpoint Lab pool are untouched. The protocol evidence of [3.1.0](3.1.0-source-audit.md) is unchanged; `npm run evidence:check` is part of the release checks.

## Protocol surface

Without presets, or with `routeMode=full`, nothing changes: checked against `v3.1.9` on the local oracle stand (real handler, fake Cloudflare registration, the 68 parameter sets of 3.1.7, 8 runs each, `.conf` structure and fixed fields): no set differs, and 1000 router configs stay within `Jc ≤ 2`, `40 ≤ Jmin ≤ 64`, `Jmin + 64 ≤ Jmax ≤ 128`. A broken snapshot cannot reach this path: the full tunnel never reads it (mutation gate, below).

Transitional presets were checked against `v3.1.9` on a split stand: both handlers under one fake network, opencck answering with the public lists recorded by the 3.1.9 measurement of 2026-11-01 (nothing for the sites of a preset that got the antifilter fallback that day, as opencck answered then), the itdoginfo lists failing. 74 sets: YouTube, Instagram, Facebook, WhatsApp, Discord, their mixes, `count=3`, `mobile=1`, `ipv6=1`, `router=1` and Lab Auto in the four modes (56), and one AWG 2.0 set for each of the 18 presets kept transitional by the coverage check (Telegram with the nine networks of `cidr.txt` that 3.1.9 added to its lists). For every config the IPv4 part of `AllowedIPs`, as a set of addresses, equals `v3.1.9`; the IPv6 part equals `v3.1.9` minus `2606:4700:d0::/48` and `2606:4700:d1::/48`; every other line and response field is equal (keys, junk sizes and CPS bytes compared by shape, the Lab endpoint a pool member on both sides); `vpn://` carries the same `.conf`. In the two mixes with catalogue presets (Discord with Steam, YouTube with Cloudflare and GitHub) the release set equals the transitional part of `v3.1.9` together with the snapshot records, minus the four WARP `/24`. One field differs by design: RuTracker counts six sites, not four, since it took `rutracker.me` and `rutracker.nl` from `rutracker_local`. What those two domains would add when opencck answers for them is not shown by the stand.

Every preset key of `v3.1.9` (49) was sent through the release handlers (alias gate): `/api/warp` answers 200 for each, except a retired key alone (`400 empty_split_tunnel` before registration); `rutracker_local` answers as `rutracker` and is named so in `routesPresets`; a retired key in a mix is skipped with `Presets retired:`; `/api/iplist` never answers 400 for them; a settings link naming any of them either selects a preset or names the key in the routes note, none is lost silently.

Invariants on the new paths, each with a test through the handler: I14 now covers IPv6 — with `ipv6=1` the IPv6 part is `S6 \ (E6 ∪ O6)`, entries off the subtrahend unchanged, IPv6 never merged (`__tests__/invariant-i14-route-aggregation.test.js`, `route-aggregation-api.test.js`); new I15 — a split `AllowedIPs` never covers the config's `Endpoint` in hostname mode, Lab Auto, the built-in endpoints of `awg2_random` and `awg2_dpi` (also with the `cloudflare` preset of the snapshot, whose `188.114.96.0/20` holds built-in candidates, on port 4500) and with a manual endpoint (`__tests__/invariant-i15-endpoint-outside-routes.test.js`); I11 — Lab Auto still changes only `Endpoint`, answers `503 lab_endpoints_in_routes` when every fresh endpoint is inside the routes and checks Lab readiness before the route lists (`invariant-i11-lab-auto.test.js`, `warp-route-preresolve.test.js`, `e2e/lab-auto.e2e.js`); I6, I7, I10 and the 3.1.8 degradation are tested on both paths: on the transitional one with Discord (`route-aggregation-api.test.js`), on the catalogue one with GitHub, a preset with IPv6 networks — IPv6 routes with `ipv6=1` and none without it or with `mobile=1` (`preset-catalog-api.test.js`; `api/warp.js` drops IPv6 for `mobile=1` in two places, and the test fails only when both are removed), `vpn://` carrying the same `.conf` and `allowed_ips`, and a registration without IPv6 dropping the IPv6 routes of its own config only (`route-aggregation-api.test.js`). I11 runs on the catalogue path with Cloudflare (`invariant-i11-lab-auto.test.js`) and on the transitional one with Discord (`route-aggregation-api.test.js`). No invariant is weakened. Test expectations that changed are commented in place with their reason (the reserve instead of antifilter, the snapshot instead of static lists, the Lab order).

## The catalogue

`src/server/ipCatalog/snapshot.json` (schema 1) holds, per preset, the IPv4 and IPv6 networks, the date each resolved address was last seen, the precision and, for a transitional preset, the line count of its live lists at the build and its reserve. It is read once, lazily, on first use (a split request or the catalogue listing of `/api/iplist`); a file that is missing or fails the strict parse refuses split requests with `503` and a fixed text before Lab Auto and registration. `npm run ipcatalog:check` (inside `npm test`) checks the committed file without network: sorted keys and lists, every preset of `routePresets.js` present, no bogon, no network wider than `/8` outside an official list that allows it, nothing to merge, more than 300 routes only with `wide`, transitional presets as `routePresets.js` marks them.

The builder (`scripts/ipcatalog/`, maintainer's machine only, never in the request path or CI) takes one `now` for the whole run and gives the same file for the same answers (`__tests__/ipcatalog-build.test.js`); a failed source or a `stale` record exits 1. The rekryt/iplist configs are read at one pinned commit (`ae442d03331bd79bce03558bbf03322d39b34f47` in this build); every source is recorded in `sources` with its URL, time and SHA-256 (`sha256Digest`).

## Mutation

`release-gates-3.2.0/mutation-gate.js`: 32 mutants, each fails its tests. The antifilter substitute back; Telegram without the nine networks of `cidr.txt`, or those networks alone standing in for an empty answer instead of the reserve; an empty answer cached again; a transitional preset without its reserve; a catalogue preset going to the network at request time; an alias not applied in the settings link; a retired key in a mix refused as unknown; a preset without data included silently; a set of retired presets only not refused; the IPv6 cut skipped, one `/48` missing from it, `exclude6` subtracting nothing; a manual endpoint inside the routes not cut, an invalid one accepted; the Lab candidate filter skipped, Lab Auto without candidates going to hostname, `lab_endpoints_in_routes` missing from the Lab codes, Lab readiness checked after the routes; the built-in endpoints not filtered; `routes4` and the tile price without the cut; the quick pick not `PRESET_QUICK_PICK`; `/api/iplist` with `ipv6=1` losing the IPv4 part; `[preset-stats]` writing an IP; the builder writing unsorted lists, taking the date from the clock, accepting `stale`; a network wider than `/8` or a bogon accepted; a broken snapshot breaking the full tunnel; the page counter counting the raw `count4`.

## Measurement

The snapshot was built on 2026-11-01 (`builtAt` 16:31:15Z; an earlier build of the same day, 14:26:27Z, still held Telegram in the catalogue) from the maintainer's workstation, which goes out through a VPN client; no `/api/warp` call and no registration. DNS answers are those of Google DoH for the client subnets `95.165.0.0/24` (MGTS, Moscow), `178.70.0.0/24` (North-West Telecom, Saint Petersburg) and `85.214.0.0/24` (Strato, Berlin), each checked against RIPE; whether real clients in Russia resolve the same addresses was not measured for this build. The line counts of transitional presets are the answers of opencck and itdoginfo to the same workstation at the build. The numbers in the release notes and the CHANGELOG are recomputed from the snapshot, the build summary and the 3.1.9 measurement by a separate check.

The coverage reference (the addresses opencck has seen for a portal, and the Moscow/Saint Petersburg resolution of antonme/ipnames) is used only in the build summary; nothing of it enters the snapshot. The spec applies the 90 % rule to the 17 presets that took opencck addresses in 3.1.9 and, by its second item, to official and AS recipes that did: Telegram. All 18 were below it (the highest, HDrezka, 86.0 %) and stayed transitional. Telegram covers 21 of the 412 reference addresses (5.1 %); the first version of the summary missed the second item, and the owner decided on 2026-11-01 to keep Telegram on the live lists of 3.1.9. What the other 391 addresses serve was not checked. Steam's own two domains resolved outside its AS; the spec gives coverage only for information to presets that had no address of their own in 3.1.9.

## Privacy

The privacy text names the access log of the web server. Checked read-only on the production host on 2026-11-01: `/etc/logrotate.d/nginx` rotates `/var/log/nginx/*.log` daily and keeps 14 rotated files besides the current one (the oldest then dated 2026-10-19), so a line lives about 15 days; `amnezia-web.access.log` is written with the format `amnezia` of `/etc/nginx/sites-available/amnezia-web`: client address, time, request line, status, bytes sent, request and upstream times, referrer and browser string. `[preset-stats]` holds preset keys and counts only (`preset-catalog-api.test.js`; the mutation that adds an address is killed).
