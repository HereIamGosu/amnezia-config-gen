# AmneziaWG Config Generator 3.1.3

## The vpn:// link connects in AmneziaVPN

Prepared on 2026-10-22 after 3.1.2 (`424820d`).

## What changed for users

The `vpn://` link for AmneziaVPN carried only the text of the `.conf` plus `mtu` and `port`. AmneziaVPN does not start a tunnel from that text: when it connects it reads separate fields of the saved profile. On iOS this failed in the network extension (AmneziaVPN 5.0.3.0 log: `Can't parse WG config … Path: hostName … found null`), so the Connect button did nothing visible, although the import itself succeeded. Importing the `.conf` file worked because the client builds those fields itself.

The link now carries the same fields the client stores after importing a `.conf`: the Endpoint host and port (a number), the private key, the address, the server public key, the allowed IPs, the MTU, the keepalive and every AWG key present in the config (`Jc`, `S1`, `H1`, `I1` and so on). The `.conf` text inside the link is unchanged. The `hostName` of the link is now the host of the Endpoint in the config (before it was always `engage.cloudflareclient.com`, also for Lab Auto, whose Endpoint is an IP address).

If a link you copied before this release does not connect, generate it again or import the `.conf` file.

## AWG profiles and the API

`/api/warp` returns the same configs. Only the content of `vpnLink` changes (more fields in the packed JSON). AWG 3.0 still has no `vpn://` link.

## Evidence boundary

- Checked in the AmneziaVPN source (tag 5.0.3.0, `de93650a`): the iOS extension decodes `WGConfig` with required `hostName`, `port` (number), `client_ip`, `client_priv_key`, `server_pub_key`, `allowed_ips`; Android (`Wireguard.kt`) and desktop (`localsocketcontroller.cpp`) read the same fields. A test compares the link with a reimplementation of the client's own import (`ImportController::extractWireGuardConfig`) for six profiles.
- Seen on a device before the fix: AmneziaVPN 5.0.3.0 on iOS 26.6, the link failed as described, the `.conf` file imported and connected.
- Not checked: the new link on a device (iOS, Android, desktop). `docs/manual-checks/vpn-link-ios.md` has the checklist; the result field is empty.
- Not checked: whether the same defect explains earlier reports of AWG 3.0/3.1 not starting in AmneziaVPN 5.0.x on desktop; the reports do not say how the config was imported.

## For developers

- `src/server/vpnLinkBuilder.js`: `buildLastConfig` builds the inner JSON; the file header describes the shape.
- `__tests__/vpn-link-client-fields.test.js` (new) and `__tests__/invariant-i10-vpn-link-roundtrip.test.js` (port is now a number); invariant I10 in the README is extended.

## For the operator

A push to `main` deploys it. No host, controller or Endpoint Lab change. Smoke: `X-App-Revision`, `/`, `/en`, `/api/status`; one generation with `link=1` (it creates a WARP device) and an import of the link on an iPhone. Rollback: `amnezia-deploy rollback` returns 3.1.2.
